## สำรองและการตรวจสอบ

สำรองก่อนแทนที่สำเร็จอยู่ที่ `output/db264-backups/2026-10-07T21-19-46-154Z/`
มี `snapshot.json`, `restore-data.sql`, `schema.sql` และ checksum
ข้อมูลเดิมมี users 2 แถวและ patients 2 แถว สามารถกู้ข้อมูลเดิมด้วย `restore-data.sql`
ใน db264 ที่มี schema เดิม การกู้จะลบข้อมูลปัจจุบันทั้งหมดก่อนคืนข้อมูลสำรอง
ห้ามรันกู้ถ้าต้องการเก็บข้อมูลที่เพิ่มหลังจากแทนที่แล้ว

ใช้ DELETE/INSERT ภายใน transaction เดียว ไม่ DROP/TRUNCATE ตาราง
ตรวจ foreign key ตลอดการทำงาน ตรวจแถวและข้อมูลก่อน commit
รหัสผู้ใช้ใหม่ไม่ซ้ำของเดิม ป้องกัน JWT ของบัญชีเก่าตรงกับบัญชีใหม่
รอบแรกพบลำดับคอลัมน์ไม่ตรงกันและ rollback สำเร็จก่อนรอบที่ commit นี้

สคริปต์ใน backend (อ่านค่า backend/.env และปฏิเสธเป้าหมายอื่น):

```cmd
node scripts/replace-db264-demo.cjs
```

คำสั่งด้านบนแสดง preview อย่างเดียว การเพิ่ม `--replace-db264` จะล้างและแทนที่ข้อมูลจริง
สร้าง backup และรหัสผ่านชุดใหม่ทุกครั้ง ไม่ควรรันซ้ำเพื่อเช็กสถานะ

ตรวจจำนวนหลัง commit, login 3 Role และอ่านข้อมูลผ่าน API โดยไม่มีการเขียนข้อมูล:

```cmd
node scripts/verify-db264-demo.cjs
```

ปรับ backend ให้แปลง JSON ที่ MariaDB ส่งเป็นข้อความก่อนคืนตัวเลือกแบบประเมิน
และคำตอบ mood เพื่อให้หน้าเว็บได้ array/object เหมือนตอนใช้ MySQL
หลังการเปลี่ยนนี้ให้ restart backend พอร์ต 3001 หนึ่งครั้ง แล้ว logout/login ด้วยบัญชีใหม่
ไม่ต้อง build frontend หรือเปิด tunnel ใหม่สำหรับการเปลี่ยนฐานข้อมูลครั้งนี้
