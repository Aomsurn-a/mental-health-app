# Chat Summarizer

เข้าใช้งานด้วยบัญชีนักจิตวิทยา → แชท → เลือกผู้รับบริการ → **สรุปแชทให้หน่อย**
เลือก 5/20 ข้อความล่าสุด, ทั้งหมดในเดือนนี้ หรือช่วงวันที่เอง แล้วกด **สรุปข้อความ**
ผลเป็น bullet ไม่เกิน 5 ข้อ พร้อมจำนวนข้อความและเวลาข้อความแรก/สุดท้ายใน modal เดิม

## Flow

1. ตรวจ JWT และ role psychologist จากนั้นตรวจบัญชีจริงและนัดหมายร่วมกันก่อนอ่านแชท
2. รับตัวเลือกชนิดเดียว: จำนวนข้อความ หรือวันเริ่ม/วันสิ้นสุด
3. อ่านเฉพาะข้อความ active ของคู่นักจิต–ผู้รับบริการที่ระบุ ช่วงวันที่ใช้ Asia/Bangkok รวมวันสิ้นสุดจนก่อนเที่ยงคืนวันถัดไป
4. ช่วงวันที่อ่านได้สูงสุด 201 รายการเพื่อเช็คว่ามากกว่า 200 หรือไม่ หากเกินคืน error ก่อนเรียก AI ไม่มีการตัดข้อความเงียบ ๆ
5. เรียง sent_at แล้ว id จากเก่าไปใหม่ ส่งบทบาทผู้พูด เนื้อหา และเวลาให้ `claude-sonnet-4-6` ผ่าน `/claude-native/v1/messages` ของ MaxPlus ด้วย key เดิม
6. ตรวจ JSON ว่ามี summary 1–5 ข้อแล้วแสดงใน modal ไม่สร้าง cache และไม่บันทึกผลลงฐานข้อมูล

ตัวเลขจำนวนข้อความและ dateRange มาจากฐานข้อมูล ไม่ให้ AI สร้าง การส่งไป MaxPlus ไม่แนบชื่อ อีเมล หรือรหัสบัญชี แต่เนื้อหาแชทยังคงมีข้อความที่คู่สนทนาเขียน

## API

`POST /api/psychologist/chat/:patientId/summarize`

```json
{"lastNMessages":20}
```

หรือ

```json
{"startDate":"2026-08-01","endDate":"2026-08-31"}
```

patientId คือ users.id ของผู้รับบริการ; N เป็น integer 1–200
dateRange ใน response เป็นช่วงเวลาของข้อความที่นำมาสรุปจริง พร้อม offset +07:00

- 400: ตัวเลือก/ช่วงวันไม่ถูกต้อง หรือส่งสองโหมดพร้อมกัน
- 401/403: ยังไม่เข้าสู่ระบบ ไม่มี role หรือไม่มีนัดหมายร่วมกัน
- 404: ไม่มีข้อความในช่วงนั้น (ไม่เรียก AI)
- 422: มากกว่า 200 ข้อความ ให้เลือกช่วงแคบลง
- 502: AI ล้มเหลวหรือคำตอบไม่ตรง schema ให้ลองใหม่

## ทดสอบด้วยข้อมูลตัวอย่าง

ต้องมีบัญชีผู้รับบริการ, psychologists ที่เชื่อมกับบัญชีนักจิต, appointment ระหว่างสองคน และ chat_messages ระหว่าง users.id ทั้งสอง
ไม่ต้องเพิ่มตารางใหม่หรือรัน migration สำหรับฟีเจอร์นี้

```bat
cd /d D:\Work\Final_project\mental-health-app\backend
npm run test:chat-summary
node tests/chatSummary.integration.cjs --live
```

ทดสอบบนฐานข้อมูล `mental_chatsummary_test_<timestamp>` แยก ใช้ข้อความจำลอง และลบฐานทดสอบเมื่อจบ
`--live` เรียก MaxPlus จริงด้วยข้อมูลจำลอง; ไม่ใช้ข้อความผู้รับบริการจริง
เพิ่ม `--browser` เมื่อเปิด Vite ที่พอร์ต 5188 และตั้ง PLAYWRIGHT_PATH เพื่อทดสอบ UI

ตรวจด้วยมือ:

1. เลือก 5/20 ข้อความล่าสุด ตรวจว่าจำนวนแสดงตรงกับจำนวนที่มีจริง
2. เลือกช่วงวันที่ให้มีข้อความที่ 00:00 และ 23:59 ของวันสิ้นสุด ตรวจว่าถูกรวม
3. เลือกช่วงไม่มีข้อความและช่วงเกิน 200 ข้อความ ตรวจ error ใน modal
4. ทดลองด้วยนักจิตคนอื่นที่ไม่เคยมีนัด ต้องไม่สามารถเรียก API อ่านหรือสรุปแชทได้
5. ปิด modal หรือเปลี่ยนคู่สนทนาระหว่างรอ ผลลัพธ์เก่าต้องไม่แสดงบนคู่สนทนาใหม่
